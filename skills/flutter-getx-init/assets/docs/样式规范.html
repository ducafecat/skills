DucafeUI 样式规范

从主题 token 到页面组合，让颜色、层级和交互保持一致。

查看组件说明 ↗

本文约定 TubeFlow Flutter 项目的样式组织、组件选用与页面实现方式，适用于 lib/common/widgets 和业务页面。数值依据当前源码整理；尺寸均为 Flutter 逻辑像素，文字行高为字号的倍数。

视觉设计见设计规范，组件职责见组件抽取规范，构造参数与示例见组件说明。本文中的数值表记录 Flutter 当前实现；设计调整时，应同步更新 token、组件及文档，不在页面局部维护另一套值。

GUIDELINE / 01

1. 样式来源与目录

AppStyle 是运行时主题数据的唯一来源。AppTheme 将其映射为 Material 3 主题，公共组件通过同一组 token 读取颜色、文字和表面效果。

职责源码入口使用约定
亮暗主题数据app_style.dart集中定义颜色、渐变、阴影及玻璃开关
Material 组件主题app_theme.dart统一按钮、输入框、卡片、AppBar、对话框等默认样式
语义颜色访问app_colors.dart页面使用 context.app*，状态色使用 AppColors
字体层级app_text_styles.dart使用语义样式及其 *On(context) 方法
圆角app_radius.dart优先使用 card、button、input、sheet 等语义名
间距与断点adaptive_spacing.dart、adaptive_breakpoints.dart页面留白、组件间距和响应式分界集中维护
玻璃效果app_glass.dart、surface.dart复用 AppGlass 和 GlassSurface
媒体与品牌例外app_media_colors.dart使用 AppMediaColors、AppBrandColors

页面、main.dart 和 global.dart 导入公共总入口：

DART / 示例
import 'package:flutter/material.dart';

// 页面统一使用公共总入口，避免逐个导入样式实现文件。
import 'package:{{package_name}}/common/index.dart';

common 内跨子目录依赖使用目标子目录的 index.dart；同目录文件直接导入。公共总入口只导出各子目录入口。新增样式文件、公共组件时同步维护对应的 index.dart，代码加中文注释说明用途和例外原因。

GUIDELINE / 02

2. 颜色与主题

页面按语义取色，不内联 HEX，不通过 isDarkMode 分别拼装亮暗配色。新增主题色先加入 AppStyle，同时维护亮色、暗色、copyWith、lerp 和必要的 Material 映射。

下表使用 Flutter 的 0xAARRGGBB 表示法；前两位为透明度，不能直接当作 CSS 的八位 HEX 顺序使用。

appCard 在关闭玻璃时自动回退为 appSurface。主操作前景在两套主题下均为深色，不要自行替换成白字。错误文字与危险操作背景用途不同，表单报错应使用 appErrorText。

AppColors.success、warning、danger 分别为 0xFF10B981、0xFFF59E0B、0xFFEF4444，用于状态表达；状态仍需配合文字或图标，不能只靠颜色区分。播放器、图片遮罩与品牌按钮使用集中定义的媒体和品牌色，避免向普通页面扩散固定黑白配色。

主题模式由 AdaptiveTheme 管理，提供浅色、深色、跟随系统。业务页面不另存一份主题开关，也不绕过 AppTheme 重建独立色板。

3. 字体与文字层级

样式字号字重行高典型用途
display30w7001.2引导页大标题
pageTitle / sectionTitle20w7001.25页面及分区标题
cardTitle16w6001.4卡片标题
body15w4001.65正文、主要说明
secondary / meta13w4001.5次要说明、元信息
caption / label12w4001.5辅助标签、提示
mono12w5001.4等宽数据、代码

优先使用 AppTextStyles.bodyOn(context) 等带主题颜色的方法。裸样式主要描述字号、字重和行高；需要局部变化时通过 copyWith 修改，并继续使用语义颜色。

Flutter 当前未统一指定 Inter 字体，普通文字沿用平台字体，mono 指定 monospace。HTML 设计稿的展示字体不代表 Flutter 已打包同名字体。

保留系统文字缩放，不用固定高度裁剪正文、按钮文案或错误提示。标题是否省略、正文是否换行由内容用途决定；不得为隐藏溢出而统一设置单行。多语言使用 TrKeys 与 AppTranslations，至少检查 en、zh-CN、zh-TW 的长度差异。

4. 间距、圆角与尺寸

4.1 间距

Token值用途
AppSpacing.page20页面水平留白
AppSpacing.card16卡片内部留白
AppSpacing.sheetTop14底部面板顶部间距
AppSpacing.sheetBottom30底部面板基础底部间距
AppSpacing.touch48触控尺寸基准
xs / sm / md8 / 12 / 16紧密到常规组件间距
lg / xl / xxl24 / 32 / 40内容分组与大块留白

优先引用命名 token。安全区、键盘高度和设计稿缩放值是运行时量，不应替换成固定间距。HTML 展示卡片的留白不直接套到 App 页面。

4.2 圆角

Token值用途
AppRadius.card16卡片及当前 Material 对话框
AppRadius.button / input12按钮、输入框
AppRadius.sheet / modal28底部面板、选用该 token 的自定义弹层
AppRadius.pill999胶囊外形
sm / md / lg / xl4 / 6 / 8 / 12既有小元素尺寸，新增实现优先用语义名

注意现有快捷值并非完全同名映射：modalBorderRadius 使用 sheet，chipBorderRadius 使用 lg。不能假定所有对话框都是 28，或所有 Chip 都是胶囊；应遵循具体组件的默认外形。

4.3 组件尺寸与触控

WidgetScale 提供 small、medium、large。当前 ButtonWidget 与 TextWidget 的缩放系数为 0.8、1.0、1.3；各组件按自身实现解释档位，不等同于全局页面缩放。

AppButton 普通最小尺寸为 48 × 42，prominent 为 48 × 48。顶部玻璃图标按钮视觉尺寸可为 32，但外层触控区域至少为 48 × 48；顶部文字动作同样区分视觉高度与触控高度。不要通过缩小外层约束压缩已有触控区域。

GUIDELINE / 05

5. 表面、玻璃与阴影

使用 GlassSurface 统一裁切、背景、模糊、边框及阴影。顶部玻璃模糊基准为 AppGlass.blurHeader = 22，轻量表面为 blurLight = 10。

颜色、渐变和阴影从 AppGlass 或 context.appStyle 读取。卡片阴影、底部面板阴影和对话框阴影各有用途，不在页面中复制 BoxShadow 列表。玻璃层应保留 Material 点击反馈，避免背景盖住 InkWell 或 ListTile 的反馈。

关闭全局玻璃使用 AppTheme.build(brightness, glassEnabled: false)。此时 GlassSurface 停用模糊和渐变，改用不透明表面，圆角裁切仍生效。单个组件的 enableBlur: false 仅关闭模糊，不等同于全局不透明降级。避免在滚动列表中叠加不必要的多层模糊。

GUIDELINE / 06

6. 页面布局与适配

普通页面优先复用 PageScaffold，由其提供背景、安全区和水平留白。默认水平 padding 为 AppSpacing.page；列表自己管理留白时显式使用 fullBleed 或传入 padding，避免重复叠加。

布局优先使用 Expanded、Flexible、Wrap、LayoutBuilder 和内容约束。文本区域允许自然增长；滚动内容和固定底部操作区应明确各自的高度约束。

AdaptiveBreakpoints宽度
smallPhone360
phone390
largePhone430
tablet600
desktop1024

以上是可供布局选择的断点常量，不会自动切换列数。根据当前可用宽度选择布局，不仅依据设备名称判断。

ScreenAdapt 可按设计稿温和缩放：圆角系数限制在 0.95–1.12，图标在 0.95–1.10，字体在 0.98–1.08。其现有 isSmallPhone 使用 375，和 AdaptiveBreakpoints.smallPhone 的 360 不同；新增断点布局统一引用 AdaptiveBreakpoints，不要混用两者推断同一分界。

避免对同一个尺寸叠加 ScreenUtil、ScreenAdapt 和 WidgetScale 多重缩放。安全区使用 SafeArea 或已有 safeTop / safeBottom 扩展；键盘遮挡通过 MediaQuery.viewInsetsOf(context) 处理。底部菜单需同时考虑键盘、手势条和大字模式。

GUIDELINE / 07

7. 组件与交互状态

标准公共组件来自 lib/common/widgets，具体 API 以组件说明和对应源码为准。新增页面先选用已有按钮、卡片、列表项、输入框、状态页和弹层；局部组合留在页面内，具有业务语义的共享组合放入 common/components。

场景实现约定
主要操作选择 PrimaryButton 或现有 primary 变体，保留主题前景与背景配对
次要操作使用 Ghost、outline 等已有变体，避免与主操作争夺强调层级
删除等危险操作使用 destructive 语义，需确认时复用确认对话框
异步操作展示加载状态并阻止重复提交；AppButton 保留文案占位，ButtonWidget 在内容旁显示指示器
图标操作提供 tooltip 或语义标签，保留触控区域和键盘焦点反馈
表单使用主题输入边框，保留邮箱键盘、密码遮蔽等输入语义；错误文字可换行
空数据与失败复用状态组件，明确说明状态并按需要提供重试入口
底部菜单使用 showModalBottomSheet 或匹配需求的已有面板；通过弹层自身 context 的 Navigator 关闭

当前 AppFormField 不提供 keyboardType、obscureText 参数。需要这些能力时，选用支持它们的输入组件或使用继承 InputDecorationTheme 的 Material TextField，不要给封装组件传入不存在的参数。

主题菜单提供浅色、深色、跟随系统；语言菜单提供 en、zh-CN、zh-TW。页面跳转使用 go_router；关闭弹层使用 Navigator.of(sheetContext).pop(...)，禁止 Get.back。

新增动画应表达状态变化或层级切换，并考虑系统减少动画设置。当前没有统一动画时长 token，不应把某个页面的过渡时间当作全项目标准。

GUIDELINE / 08

8. 页面组合示例

下面的组合复用页面留白、字体、间距及按钮样式。示例仅展示布局，实际文案使用项目已有翻译键。

DART / 示例
/// 简单设置页内容：调用方传入已翻译的文案与保存行为。
Widget buildSettingsBody(
  BuildContext context, {
  required String title,
  required String description,
  required String saveLabel,
  required VoidCallback onSave,
}) {
  return PageScaffold(
    scrollable: true,
    body: Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        const SizedBox(height: AppSpacing.lg),
        Text(title, style: AppTextStyles.pageTitleOn(context)),
        const SizedBox(height: AppSpacing.xs),
        Text(description, style: AppTextStyles.secondaryOn(context)),
        const SizedBox(height: AppSpacing.lg),
        PrimaryButton(label: saveLabel, onPressed: onSave),
      ],
    ),
  );
}
GUIDELINE / 09

9. 修改与验收

修改主题时先改集中 token，再检查 Material 映射与公共组件，最后同步设计及使用文档。新增例外需在代码注释中说明用途和原因，不把单页修补扩散成全局规则。

验收至少覆盖与改动相关的情况：

  • 亮色、暗色、跟随系统，以及透明表面叠在真实背景上的效果。
  • 窄屏、宽屏、横屏、系统大字，避免溢出和内容裁切。
  • 中英文及繁体文案，标题、按钮和错误提示长度变化。
  • 默认、按下、焦点、禁用、加载、失败等实际支持的状态。
  • 图标语义、键盘操作、触控区域、安全区及键盘弹出后的可达性。
  • 玻璃开关切换后内容仍可读，圆角与点击反馈仍正确。

相关回归测试见 app_style_test.dart、style_widgets_test.dart、widgets_test.dart。改动样式或组件时运行对应测试与 flutter analyze；仅修改文档时核对源码数值、API、示例和链接即可。HTML 组件说明是开发参考，不替代 Flutter 实机视觉验收。
