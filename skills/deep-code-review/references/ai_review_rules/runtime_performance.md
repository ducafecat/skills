# 运行时性能检查

## 检查范围

- 请求或任务热路径新增串行等待、同步阻塞，或把可并行工作串行化。
- 循环内数据库/网络调用、远端扇出和逐条处理造成的 N+1。
- 高频查询的过滤、排序、索引与查询范围是否导致扫描放大。
- 分页、游标和排序顺序是否导致全量读取、重复扫描或翻页漂移。
- 大对象、大字段、集合、文件的构造、序列化和一次性 IO。
- 重复计算、缓存键或失效策略是否导致稳定的额外开销。
- 锁粒度、事务时长、连接持有和池容量是否在并发下放大等待。

## 成立条件

- 必须给出触发路径和规模条件，例如列表长度、数据量或并发量。
- 说明开销如何随规模增长，并落到延迟、吞吐、内存、IO 或连接占用。
- 索引问题必须有本次查询形态和可见 schema/索引证据。

## 不报告

- 微优化、常数级差异或只有“将来数据大了可能慢”的推测。
- 不在实际运行路径上的测试、构建期或一次性维护代码。
- 只借性能名义提出结构重构，但无法证明当前运行开销。
