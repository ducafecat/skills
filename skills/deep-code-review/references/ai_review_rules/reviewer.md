# 通用正确性检查

## 检查范围

- 空值、类型、边界、索引、条件分支和状态转换是否产生错误结果。
- 异常、部分失败、取消、超时与清理路径是否保持一致状态。
- 异步与并发代码是否存在竞态、重复执行、悬空任务或错误吞没。
- 文件、连接、流、订阅、锁和内存等资源是否在所有路径释放。
- 变更中的重复逻辑是否可能产生行为漂移，关键逻辑是否因强耦合而无法隔离验证。

## 成立条件

- 必须给出具体输入或执行顺序，并说明代码将产生的错误结果。
- 重复与可测试性问题必须已经影响正确性或显著增加本次逻辑的验证难度；单纯存在相似代码不成立。

## 不报告

- 纯代码风格、格式、静态工具能够直接发现的问题。
- 只涉及架构、安全、性能、部署或产品偏好的意见；交给对应规则。
- 没有当前调用路径或数据条件支持的防御性猜测。
